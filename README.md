# neomega-viewer-r2：存档射线浏览器

neOmega Viewer R2 前身是 neOmega Viewer (https://github.com/CMA2401PT/neomega-viewer)，但是采用了全射线渲染器 (neOmega R2, https://github.com/CMA2401PT/neomega-r2)，这使得其很适合大可视区块高性能渲染&光影支持。

这个应用把 Java／Bedrock 存档读取、流式调度和 R2 统一射线核心组合成可运行的浏览器。整个可见范围使用完整静态模型，包括栏杆、楼梯、花和跨格模型。近景额外启用已注册的 effector、block actor；静态形状不随近景距离改变。Go 对静态区域只做调色板映射。

启动后显示内置默认场景 **Möbius**：海晶灯组成的莫比乌斯环立在无限海面上，夜幕中的月亮和灯环倒影共同构成开场画面。服务端把灯环作为普通方块来源，浏览器沿用存档的区域流式加载与地图；海面由渲染器按解析平面绘制。

屏幕底部悬浮的工具栏（HUD）提供来源选择、坐标和设置。文件夹按钮可以打开服务端机器上的 Java／Bedrock 世界目录、`level.dat`、Java PackFS 单文件和结构文件。原生存档与 PackFS 均只读打开。关闭存档会回到 Möbius 的开场视角和夜间时刻。

## 启动与使用

在工作区根目录运行：

```sh
go run ./apps/neomega-viewer-r2/cmd/viewer -listen 127.0.0.1:2412
```

启动终端先显示准备阶段，完成后显示 WebUI 地址并打开默认浏览器。`-browser=false` 只显示地址，适合远程运行或浏览器验收。`-version` 打印版本后退出。

浏览器访问 <http://127.0.0.1:2412>。Java 世界按维度的 `region` 目录读取，Bedrock 世界按 `db` 目录读取。

Windows 上直接运行 `neomega-viewer-r2.exe` 即可：它启动服务，并用独立 Chrome／Edge 配置打开 1240×840 的应用窗口，浏览器设置与日常浏览器分开。默认用 Edge + Vulkan 打开，没装 Edge 时依次换 Chrome + Vulkan、Chrome + OpenGL。终端里列出 `Edge + Vulkan`、`Chrome + Vulkan`、`Chrome + OpenGL` 三个按钮，打不开、黑屏、很卡或一直在编译时，直接点按钮（或按数字键 1～3）用另一种组合再开一个窗口；为了能点击，终端的快速编辑（单击选字）在运行期间关闭。`-open` 指定启动时用的组合（`edge-vulkan` 默认、`chrome-vulkan`、`chrome-gl`；`system` 表示系统默认浏览器且不带参数），`-browser=false` 只起服务。每种组合使用独立的浏览器配置目录，按 exe 旁的 `runtime/`、`%LOCALAPPDATA%`、临时目录取第一个可写的。不指定 ANGLE 后端时浏览器默认用 Direct3D 11，AMD 780M 上已复现大型射线程序编译过慢，所以不用它；初始化期间页面顶部显示正在编译哪个射线程序以及已用时间。

每次启动都在 exe 旁写一份 `neomega-viewer-r2-log.txt`（不可写时放到用户缓存或临时目录，终端里会印出实际位置），记录程序版本、Windows 版本、找到的浏览器及版本、每次打开窗口的命令和浏览器启动进程的退出代码，以及网页上报的显卡与图形后端、射线程序编译耗时、累积模块准备、错误、WebGL 上下文丢失和运行 15 秒、60 秒时的帧率与 GPU 时间。遇到问题时把这份文件发给开发者。程序所在目录或其上级显式设置了拒绝项或低完整性标签（例如开发工具沙箱保护的工作区）时，不自动打开浏览器，也不显示按钮，只在终端明确提示把程序复制到别的目录再运行：实测从这类目录启动的 Chrome 立即崩溃、Edge 一直白屏，浏览器配置放在别处也一样。

也可启动时直接打开：

```sh
go run ./apps/neomega-viewer-r2/cmd/viewer \
  -listen 127.0.0.1:2412 -world '/path/to/java-world'
```

来源选择面板把“选择文件”和“打开”分开，方便在转换前展开选项，设置维度、Bedrock 邻接修复、结构转换内存预算与写出并发。双击目录进入其中，选择结构文件后点击“打开所选来源”；转换期间面板按读取、写出或解包阶段显示进度，关闭面板会取消转换。

打开面板的维度使用下拉选择。首次选择 Java 来源时先打开主世界，服务端返回扫描结果后可在场景信息里切换；Bedrock 直接提供三个标准维度。Java 维度使用存档内相对目录，标准维度是 `.`、`DIM-1`、`DIM1`，自定义维度使用 `dimensions/<命名空间>/<路径>`。打开时扫描可用维度并放进场景信息的下拉框。Bedrock 固定提供 `0`（主世界）、`1`（下界）、`2`（末地）。切换维度重新打开同一来源。相机优先使用出生点上方 12 格；出生点所在区块不存在时，落到所选维度已有内容附近。Bedrock 出生点 Y 超出维度范围时，从出生点区块的最高非空气 section 估算落点。

结构文件先生成可随机读取的世界：`.schem`、`.schematic`、`.litematic`、`.nbt` 生成 Java 存档，`.mcstructure`、`.mcworld` 生成 Bedrock 存档。输出在源文件旁去掉扩展名的同名目录，例如 `城堡.schem` → `城堡/`。已有存档直接复用；非空的其他目录报错并保留原内容。源文件更新后，移走旧输出目录再打开即可重新转换。场景信息会显示实际输出路径和复用状态。

结构转换默认工作预算为 512 MiB，`-structure-memory-mib` 可调整，最小 64；`-structure-workers` 指定写出并发上限，默认 0 由 CPU 和预算决定。Bedrock 默认按邻居修复栅栏连接、楼梯拐角等属性，`-bedrock-fix=false` 可以关闭。修复只影响内存中的 Java 状态。网页打开选项默认采用启动参数。

```sh
go run ./apps/neomega-viewer-r2/cmd/viewer \
  -world '/path/to/world.pack' -dimension DIM-1
go run ./apps/neomega-viewer-r2/cmd/viewer \
  -world '/path/to/bedrock-world' -dimension 1 -bedrock-fix=false
go run ./apps/neomega-viewer-r2/cmd/viewer \
  -world '/path/to/城堡.schem' -structure-memory-mib 1024 -structure-workers 4
```

渲染窗口固定为 Y `[-64,448)`。越界 section 不显示，但世界可以正常打开。场景信息显示“有 N 个 section 超出可显示高度”，按实际读取过的区块去重计数；重复下载不会重复累计。文件会话中的 `minY=-64`、`height=512` 描述这个窗口。

Go 服务端只提供文件与内置场景。R2Link 数据源将改由浏览器通过 WebSocket 直接连接，作为另一种数据源接入核心的世界会话；这部分正在重写，期间 HUD 不提供连接入口。协议草案见 [R2Link 数据源说明](docs/r2link.md)。

拖动转向，WASD 按相机的水平朝向前后左右移动，抬头低头不改变移动高度。空格沿 Y 轴上升，Shift 沿 Y 轴下降。滚轮沿视线前后移动，按住 Shift 滚动时加大步长。点击底部 X、Y、Z 读数即可编辑，回车或箭头按钮跳转，Esc 或点到别处放弃编辑。存档名打开场景信息，齿轮打开设置，面板位于触发按钮上方。默认场景和存档均可飞行、使用地图和调整光照。设置保存在浏览器本地。

触屏设备上，单指拖动场景转向，按住右下角的十字按钮水平移动，左侧两个按钮沿 Y 轴升降。移动按钮位于底部 HUD 上方，可一边按住按钮一边用另一根手指转向。隐藏 HUD 或打开全屏地图时，移动按钮一起隐藏。

右上角第一排依次是体素渲染器、基础渲染器、光影渲染器（三选一，决定预览用哪一档，见 [四档渲染器](../../neomega-r2/README.md#四档渲染器)）、静止时累积和隐藏 HUD；第二排依次是导出当前画面、拍照、时间流逝和时间滑块。隐藏 HUD 后只保留眼睛按钮，再按恢复。打开全屏地图时右上角工具栏保留，可以直接拍摄或导出鸟瞰图，地图的操作提示移到左上角。左上角显示随相机转动的坐标轴、实际渲染分辨率与 FPS。窗口宽度小于高度或 560 像素时，页面显示“仅支持横屏”。

设置分别控制近景和远景：

- 近景只控制特效与方块实体外观，默认为半径 2 区块，可调为 1～16。水平范围为圆形，垂直范围为上下 `min(半径+1,12)` 个 section。section 是 16×16×16 的存储块。
- 远景控制全部静态模型的可见范围，默认为半径 32 区块，可调为 16～96，步长 8。默认覆盖 1024×1024×512 方块，Y 为 -64..447。窗口按 128 方块对齐随相机移动，因此实际边界有对齐偏移。
- 渲染分辨率默认为窗口尺寸 1.5×，每像素一条射线。分辨率可在屏幕原生与窗口尺寸 0.5×～2× 之间选择；在系统缩放为 1 的屏幕上，1.5× 或 2× 相当于超采样。不会为了显示帧率自动降低画质。
- 预览默认使用光影渲染器，启动时只编译所选的一档。切换到尚未编译的档时，底部先显示编译提示再开始编译，对应按钮闪烁，完成前画面沿用上一档。体素与基础两档没有阴影、雾和水面效果，给较弱的设备使用。
- 动态时间默认开启。Möbius 每次载入从 19:00 开始；离开 Möbius 打开存档或结构时，时间切到白天 10:00，启动时直接载入这些来源也从 10:00 开始。外部来源之间切换沿用当前时间。以上操作均保留用户对动态时间的开关设置。动态时间让滑块随昼夜移动，一天约 4 分钟。动态时间与静止时累积互斥，打开其中一个会关掉另一个。
- 远景雾默认开启，只在远景视距边缘变浓，遮住地形的截断处；关闭后远处的地形直接截断在天空前。
- 静止时累积默认关闭。打开后，相机、窗口尺寸、设置和已发布的数据都没有变化，且视野内没有动画对象时，画面逐帧累积、越来越干净，没有样本上限，画面一变就重新开始。累积总是使用累积渲染器，与预览选的档无关。累积渲染器较大，启动时不编译；第一次打开静止时累积或拍照时才编译，期间画面底部显示提示和已用时间，预览照常。
- “导出当前画面”用当前预览档按当前视角重新渲染：尺寸为屏幕实际像素的 2 倍边长，每个像素 4×4 超采样（共 64 倍像素的样本），取满后自动保存 PNG；画面过大时按显卡纹理上限与 2400 万像素等比缩小。进行中再按一次或按 Esc 取消。
- “拍照”总是使用累积渲染器，按当前视角离屏渲染照片，光线最多反弹 4 次。照片尺寸默认为渲染画面 2×，也可与渲染画面相同。按下后画面实时显示照片逐渐收敛，按钮下方显示已累积的样本数，没有上限；满意时再按一次保存 PNG，按 Esc 放弃。光照与拍照的原理见 [核心的光照说明](../../neomega-r2/README.md#光照怎样计算)。

有待加载内容时，屏幕上方显示近景对象准备与远景覆盖。完成后显示“已加载”，约 1.5 秒后淡出。场景信息提供存档路径、静态 section 数、区域数、累计传输、区域池用量、纹理分配和 GPU 时间。

## 全屏地图

底部地图图标把同一画布切换成正交俯视图。正交投影让所有主射线平行，地图上的同一距离不会因远近而缩放。地图沿用已加载的静态模型与核心射线求交，特殊对象隐藏，远景雾关闭。主相机的位置和朝向保持不变，静止时也能逐帧累积。

地图以主相机位置为中心，初始北方朝上、俯角 70°。左键拖动平移，右键拖动旋转和调整俯角，滚轮围绕光标缩放。触屏上单指拖动平移，双指同时旋转和缩放，缩放时两指中点下的地面跟随手指。手指数变化后从当前视图继续操作。底部滑块也可以缩放。鼠标单击或触屏轻点方块显示整数坐标与命中面，“跳转”把主相机移到方块上方两格并收起地图。Esc 或“关闭”返回原视图。点到尚未加载的区域时，地图把窗口移过去，发布完成后自动沿原来的射线再拾取一次。

右上角的小面板始终显示地图操作说明，并按鼠标或触屏显示对应的手势。

地图平移只改变远景窗口中心，近景对象仍跟随主相机。地图叠加层显示主相机朝向和选中位置，收起地图后远景窗口回到主相机附近。

显示跨度超过远景窗口时，地图切换为区块占用图。占用图以浅色表示来源中存在的区块，用来浏览整个场景的分布；点击某处会定位并放大回射线尺度。

区块占用数据来自 `GET /api/world/chunks?world=<会话 id>`。每个网页会话请求一次并缓存，避免缩放时反复扫描区域文件。会话 id 与区域接口相同，旧会话请求返回 HTTP 409。Java 存档按覆盖 32×32 区块的 `.mca` 文件建立索引，Möbius 按同样的粒度登记环所在的区块；它们都与流式加载的 8×8 区块区域采用不同粒度。响应为连续的 136 字节记录：前八字节是小端 int32 的 32×32 区块区域坐标 rx、rz，余下 128 字节表示该区域的 32×32 区块。区块位序号为 `i=(cz&31)*32+(cx&31)`，第 `i>>3` 字节的第 `i&7` 位表示是否存在，低位在前。网页把每条记录变成 32×32 的离屏位图。可见范围内的区域位图先在同一张离屏画布中按区块坐标拼接，再整体按地图相机缩放旋转。采样使用最近邻，区域交界处不会因分别绘制的边缘抗锯齿而留下浅色接缝。

## 使用 Java 材质包

在“设置”里选择服务端机器上的材质包 zip 或目录，也可以输入完整路径后点击“应用”。包根目录应直接包含 `assets`。切换只改变共享静态模型使用的贴图，保留当前存档与视角；缺失或损坏的单张图片回退原版。“恢复原版”清除覆盖，路径和尺寸设置保存在当前浏览器。

支持颜色图片及同名 labPBR `_n`／`_s` 图片。labPBR 把法线、AO、高度、高光和自发光等属性保存为数据通道，核心会按颜色图相同的层号或图集区域组织它们。没有配套图时使用默认材质数据。动画贴图按 `.mcmeta` 的首帧显示。

“贴图尺寸上限”默认 128，可选 16～512。纹理数组按包内所用图片的最大尺寸统一层边长，但不超过上限；小图最近点放大，大图缩小。只选 128 上限不会把原版自动放大到 128。较高尺寸同时增加颜色、法线和高光的显存，估算公式见 [核心材质包说明](../../neomega-r2/README.md#材质包怎样替换贴图)。

应用通过 `POST /api/textures` 把路径和上限交给核心，响应包含整套贴图及匹配的透明度数据。后台线程用已缓存的存档区域重建镂空分类对应的空间目录，完成后同帧替换 GPU 资源。因此替换树叶或给石头增加透明孔时，颜色、遮挡与阴影依据的是同一份图片，切换不需要重新打开存档或重新下载区域。

例如，直接请求服务生成一份资源快照：

```sh
curl -X POST http://127.0.0.1:2412/api/textures \
  -H 'Content-Type: application/json' \
  -d '{"path":"/path/to/pack.zip","maxSize":128}' \
  -o /tmp/r2-textures.bin
```

这个接口只返回资源，不修改服务端存档会话；网页接收后负责把结果应用到自己的渲染器。

## 为什么移动不必重新加载整个窗口

网页从 `GET /api/world` 获取当前会话。`loaded: true` 表示存在可加载的来源，存档与内置场景都满足这一点。内置场景的 `name` 为 `Möbius`、`path` 为空，并额外携带 `scene`：`ocean` 是海面 Y 坐标，`camera` 包含 `position`、`yaw`、`pitch`，角度使用弧度，`time` 以小时表示开场时刻。顶层 `position` 与开场相机位置一致。存档响应省略 `scene`。`POST /api/world/open` 接收 `path`、`dimension`、`bedrockFix`、`structureMemoryMiB`、`structureWorkers`。默认返回 JSON 会话描述；请求头 `Accept: application/x-ndjson` 时逐行返回 `progress` 消息，最后返回 `world` 或 `error`。`POST /api/world/close` 返回 Möbius 会话描述，关闭会恢复内置场景；区域、对象与占用表接口共用会话编号，旧编号返回 HTTP 409。

区域接口读取和解压存档，仅把调色板条目换成方块哈希（渲染器按资源包的状态表解释），保留压缩格子索引，不生成模型、剔面或合并网格。一个区域包含 8×8 区块；服务端保留最多约 64 MiB 的区域响应缓存。Möbius 的方块和区域字节在首次读取时生成一次，之后各会话复用；它与存档共用二进制编码，对象列表为空。

加载范围、后台准备与 GPU 发布由核心的世界会话（[WorldSession](../../neomega-r2/README.md#世界会话与数据源)）负责；本应用的 `web/source.js` 是它的 HTTP 数据源，按会话的订阅下载区域与近景对象。四路请求优先读取靠近相机的区域，不再需要的区域立即取消下载；后台线程登记跨格片段并生成空域掩码；主线程每帧发布一个完成的区域，未完成部分稍后补齐。移动时复用重叠区域，离开范围的区域撤销候选并回收地址。静态窗口周围保留一圈来源区域，保证边界模型完整。近景视距变化只更新特殊对象；对象候选没有变化的静态区域不重新准备，也不重新下载索引。

来源、渲染与应用调度分为三个边界：

| 位置                                 | 责任                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------- |
| `neomega-converter-core/worldinput/` | 两个 viewer 共用的路径识别、结构准备、维度扫描、原生只读句柄与读取关闭屏障。        |
| `internal/worldsource/`              | 将原生来源接到 Java 区块；为 Bedrock 组合转换器和可选 fixer。                       |
| `internal/mobius/`                   | 海晶灯莫比乌斯环、开场取景与只读场景缓存。                                          |
| `internal/worlddata/`                | Java 区块的公共区域适配、近景对象、固定高度裁剪，以及内置场景共用的区域和地图编码。 |
| `r2link/`                            | 数据源可复用的 WebSocket 消息、JSON 头和二进制索引编解码。                          |
| `internal/server/`                   | 来源会话、区域缓存与 HTTP 接口。切换场景后拒绝旧会话请求。                          |
| `internal/filebrowse/`               | 服务端文件浏览、各类来源识别与材质包选择。                                          |
| `web/source.js`                      | 世界会话的 HTTP 数据源：按订阅排队下载区域与近景对象，取消不再需要的请求。          |
| `web/app.js`                         | 会话、材质包与照片组装，同一绘制和累积循环。                                        |
| `web/hud.js`、`overlay.js`           | 坐标编辑、弹出面板、时间控件、坐标轴和临时读数。                                    |
| `web/map.js`                         | 全屏地图相机、鼠标与触屏手势、拾取重试和区块占用叠加。                              |
| `web/controls.js`、`movepad.js`      | 主相机飞行输入与触屏持续移动按钮。                                                  |
| `web/picker.js`                      | 服务端存档和材质包目录选择。                                                        |
| `neomega-r2`                         | 共享模型、世界会话、纯数据场景准备、GPU 目录与统一求交。                            |

本应用通过 converter 组合 neomega-view-utils 的 fixer。核心 neomega-r2 保持独立，只接收 Java 状态对应的静态模型编号。远景与近景使用同一份来源索引，但 NBT 外观与特效仅由近景对象接口处理。

## 特殊对象的扩展位置

Go 入口 `cmd/viewer/main.go` 选择需要启用的 effector 和 block actor 处理器。`internal/worlddata.World.Objects` 仅扫描近景中被处理器认领的方块，将状态、位置和 NBT 交给它们。浏览器入口 `web/app.js` 注册对应类型的外观工厂。工厂返回部件、贴图、包围盒和动画，公共实例层负责格子候选与射线绘制。

附魔台的活动书已通过这条链路接入。block actor 的处理器和传输接口已连通，并通过携带 NBT 的测试处理器验证；旗帜图案、告示牌排版等具体实现尚未添加。详细契约和新增实现的方法见 [核心说明](../../neomega-r2/README.md#怎样添加-effector-和-block-actor)。含水方块暂只显示本体，不显示附加水层。

区域池预留 256 MiB，缩小视距回收池内地址，切换场景时释放旧池，并为新来源重新建立池。远景半径超过 48 时，密集存档可能超出容量，此时会显示错误，可降低远景视距。文件会话按相机流式读取固定内容，查看磁盘上的外部修改需重新打开。

## 构建与验收

网页和共享资源嵌入 Go 二进制，没有前端打包步骤。开发时可用 `-web ./apps/neomega-viewer-r2/web` 直接读取应用网页；核心网页仍取自嵌入资源，改核心后需重新编译。

```sh
./check.sh neomega-r2 apps/neomega-viewer-r2
node --test neomega-r2/tests/*.mjs
go run ./apps/neomega-viewer-r2/experiment/fixture -out /tmp/neomega-r2-java-fixture
go run ./apps/neomega-viewer-r2/experiment/fixture -out /tmp/neomega-r2-static-fixture -static
R2_URL=http://127.0.0.1:2413 node apps/neomega-viewer-r2/experiment/static-models.cjs
R2_URL=http://127.0.0.1:2413 node apps/neomega-viewer-r2/experiment/browser.cjs
R2_URL=http://127.0.0.1:2413 node apps/neomega-viewer-r2/experiment/ui.cjs
R2_URL=http://127.0.0.1:2413 node apps/neomega-viewer-r2/experiment/mobius.cjs
```

浏览器验收需先在 2413 启动应用服务，可使用 `-browser=false` 避免打开交互窗口。静态模型脚本对照近景半径 1 与 16 的同一画面，验证远景形状、跨区片段和特殊对象的独立启停。普通流式验证使用 `browser.cjs`。`ui.cjs` 验证透视与高空正交拾取，并用真实存档在 1280×720、1920×1080 下生成界面截图，结果默认写入 `/tmp/r2ui/`。

`mobius.cjs` 独立验证默认场景的流式加载、协议解码、海面绘制参数、地图、拍照和关闭恢复，并在 1280×720、1920×1080 下截图，默认输出到 `/tmp/r2mobius/`。工具路径、输出与结果解释见 [验收说明](experiment/README.md)。

Windows amd64 一键编译打包（需要 Go 和包含 `go.work` 的完整工作区）：

```bat
apps\neomega-viewer-r2\build-windows.cmd
```

也可双击 `build-windows.cmd`。找不到 Go 时传 `-GoCommand "C:\path\to\go.exe"`，可用 `-Version v1.0.0` 指定版本；默认记录 viewer 和渲染核心的 Git 版本。脚本固定使用 `CGO_ENABLED=0`、`GOAMD64=v1`、`-trimpath` 和 `-ldflags="-s -w"`，验证 EXE 版本、架构、符号和本机构建路径，再输出 `dist/neomega-viewer-r2-windows-amd64.exe`、同名 ZIP 和 `SHA256SUMS.txt`。ZIP 包含兼容启动脚本、EXE、许可证、使用说明和构建信息。发布的 PowerShell 脚本统一使用 UTF-8 BOM 和 CRLF，并用 Windows PowerShell 5.1 解析验证，避免中文系统将 UTF-8 误读为 ANSI。两个 CMD 入口只对自身启动的 PowerShell 进程设置执行策略，不修改系统的长期策略。

其他平台或手动执行的不含调试符号构建：

```sh
mkdir -p apps/neomega-viewer-r2/dist
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' \
  -o apps/neomega-viewer-r2/dist/neomega-viewer-r2-windows-amd64.exe ./apps/neomega-viewer-r2/cmd/viewer
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath -ldflags='-s -w' \
  -o apps/neomega-viewer-r2/dist/neomega-viewer-r2-macos-arm64 ./apps/neomega-viewer-r2/cmd/viewer
```
